# EPIC：产品设计总流程（V0）

| 项 | 值 |
| --- | --- |
| 目标 | 验证"对设备说话 → 群里其他人听到原声"这条主链路 |
| 成品 | 电脑上的模拟设备（`linx-emu`）× N + 1 个云端服务 + 灵矽智能体 |
| 周期 | 5 周 / 3 人 |
| 不做 | 真机、实时对讲、RTC、位置、录音合规 |

## 一句话

用户对设备说"给夜班组说一句我快到收费站了"，2 秒后群里其他人的设备里响起他自己的声音。

## 三条链路

```
              ① 语音
   模拟设备 ──────────────▶ 灵矽（ASR / LLM）
      │                        │
      │ ② 原声上传             │ ③ tools/call（文本）
      ▼                        ▼
   我们（存储 + 投递）◀────────┘
      │ ④ message 推送
      ▼
   其他模拟设备（拉流播放）
```

| 链路 | 承载 | 谁实现 |
| --- | --- | --- |
| ① 语音 | 麦克风 PCM 上行 / TTS 下行 | B + 灵矽 |
| ② 原声上传 | 同一份 PCM，事后按需上传 | B + A |
| ③ 工具 | `tools/call`，纯文本 | A |
| ④ 投递 | 控制面 WS 消息帧 | A + B |

## 核心流程一：发消息

```
① 回车（充当唤醒词）→ 开始采集，本地滚动缓冲
② PCM 上行 → 灵矽 ASR → stt{text}
③ 用户说完 → listen stop
④ 灵矽 LLM → tools/call group.send_voice{group, text}
⑤ 服务写库，返回"好，已发给夜班组"（立即返回，不等音频）
⑥ 服务向发送方推 bind_message{id, text}
⑦ 设备按 text 匹配缓冲里的 utterance → 上传 PCM
⑧ 服务存为消息音频 → 向群成员推 message
```

关键：**先录后判**，录音开始时不知道发给谁；**能立即返回**，不阻塞在音频上；**拿不到音频才 TTS 兜底**。

## 核心流程二：收消息

```
① 控制面收到 message{id, from, audio_url, seq}
② 若正在放别的 → 排队；正在 TTS → 等 tts stop
③ 拉流播放（边下边播）
④ 播完上报 played{id} → 服务更新 last_acked_seq
⑤ 连续 3 条以上 → 只播最新一条 + "还有 N 条"
```

中断规则：**用户开口说话时，本地先静音，再发 abort 给灵矽**。等网络往返回来再静音就晚了。

## 核心流程三：建群与入群

```
建群： "帮我建个群叫夜班组" → group.create → 生成 6 位口令 → TTS 播报口令
入群： "加入 482913"         → group.join  → 校验 → 推 group_changed 给该设备
```

V0 只有这两种方式。扫码、碰一碰、围栏推荐都不做。

## 核心流程四：切群

```
"切到家庭群" → group.switch → 归一化群名 → 更新设备当前群 → 返回"现在只听家庭群"
```

歧义处理：命中多个群时反问"是家庭群还是老家群？"，不猜。

## 五条不能破的约束

| # | 约束 | 来源 |
| --- | --- | --- |
| 1 | 身份只认 `X-Linx-Device-Id`，不信模型传的 device_id | 防越权 |
| 2 | 不依赖 `structuredContent.funcs` 扩展，设备动作走自己的控制面 | 平台只保证 3 个内置 func |
| 3 | 返回文本 ≤ 40 字 | 那是要被 TTS 念出来的 |
| 4 | 本地静音先于 `abort` 信令 | 等往返会漏半句 |
| 5 | 每条消息按 `seq` 单调，设备按 `last_acked_seq` 补拉 | 离线恢复 |

## 风险

| 风险 | 应对 |
| --- | --- |
| "哪一段音频"配错 | utterance_id + stt.text 双键匹配，失败降级并打点 |
| 群名识别不准 | 别名表 + 提前攒语料，不交给 LLM 猜 |
| 多实例抢声卡 | 播放前本地锁；演示时错开 1~2s |
| 灵矽会话计费 | 只在说话窗口内连，空闲断开 |
