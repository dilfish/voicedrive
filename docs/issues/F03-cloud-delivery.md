## 背景

消息进了数据库不算发出。要让在线的设备立刻收到，离线的设备重连后也能补上。

## 做什么

控制面 WebSocket 服务端，四种帧：

| 方向 | 帧 | 用途 |
| --- | --- | --- |
| 下行 | `message` | 新消息推送 |
| 下行 | `bind_message` | 通知发送方上传原声 |
| 上行 | `played` | 设备回报已播 |
| 上行 | `heartbeat` | 10s 心跳，带 `last_acked_seq` |

- 设备连接时鉴权（`device_id + token`），注册到内存路由表
- 推送失败或设备离线：不重试，靠 `seq` 补发
- 重连时按 `last_acked_seq` 拉增量，单次最多 50 条
- 消息体带 `seq`，客户端按序播放

## 不做什么

- 不做 APNs / FCM 离线推送
- 不做已读状态之外的状态机（比如"正在输入"）

## 验收标准

- [ ] 两个设备连上，A 发消息，B 在 500ms 内收到
- [ ] B 断线期间产生的 5 条消息，重连后按序补发，无重复
- [ ] B 重复上报同一个 `played`，`last_acked_seq` 不回退
- [ ] 心跳 30s 未到的连接被清理，内存路由表不泄漏
- [ ] 1000 台模拟连接压测，广播一条消息耗时 P95 < 100ms

## 技术要点

```
device ──ws──▶ hub ──查找 group 成员──▶ 逐设备 push
```

- 路由表用 `map[deviceID]*conn` + RWMutex，V0 不需要 Redis
- `played` 幂等：只接受 `seq > last_acked_seq` 的回报
- 推送超时 1s，超时就丢弃，让补发兜底
