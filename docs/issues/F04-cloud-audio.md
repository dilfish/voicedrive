## 背景

群消息的主体是音频。原声来自设备（`bind_message` 之后上传），TTS 只在拿不到音频时兜底。

## 做什么

- 消息创建时先落一条"待补音频"状态，立即返回给灵矽
- 向发送方推 `bind_message{id, text}`
- 提供 `POST /v1/messages/{id}/audio`：
  - 校验消息属于该设备
  - 校验格式（16k / 单声道 / s16le）、时长（≤60s）、大小（≤2MB）
  - 写入对象存储（V0 写本地目录，路径可配置），更新 `audio_url`、`duration_ms`
- 超时兜底：`bind_message` 后 3s 没收到上传，调 TTS 生成后投递
- 投递时机：音频就绪 → 推 `message` 给群成员

## 不做什么

- 不做音频转码（原声直接存 PCM/WAV）
- 不做内容审核
- 不做录音归档（V0 没有"录音"概念，只有消息本身）

## 验收标准

- [ ] 上传 5s PCM，落盘后可被 HTTP 拉取，时长计算正确（字节数 / 32000）
- [ ] 非该设备的消息 ID 上传返回 403
- [ ] 超过 2MB 或格式不符返回 400，且消息仍走 TTS 兜底
- [ ] 不上传时，3s 后自动生成 TTS 音频并投递（用 mock 验证）
- [ ] 并发 50 条上传无覆盖、无丢失

## 技术要点

- 状态机：`pending → ready`；`pending` 超时触发 TTS，仍失败则标记 `failed` 并通知发送者
- URL 有效期 7 天，用签名 URL，不暴露存储路径
- 时长 = `len(pcm) / (16000 * 2)` 秒
- 存储层抽象成接口，V0 用本地目录，之后换 Kodo/S3 只改实现
