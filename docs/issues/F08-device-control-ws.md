## 背景

除了连灵矽，设备还要连我们的服务：收消息、收 `bind_message`、上报已播。这是第二条长连接。

## 做什么

- 与 `cmd/linx-emu` 现有 WS 客户端并存（两条连接，互不影响）
- 连接 `ws://.../v1/device`，带 `device_id` + token
- 收：`message`、`bind_message`
- 发：`played{seq}`、`heartbeat{last_acked_seq}`
- 断线重连：指数退避（1s → 2s → 4s，上限 30s），重连后立即心跳触发补发
- 心跳每 10 秒一次

## 不做什么

- 不做消息持久化（离线期间的消息由服务端按 seq 补发）
- 不做多连接复用（一份设备一条连接）

## 验收标准

- [ ] 服务端 kill 后，客户端 30 秒内自动重连，日志可见退避过程
- [ ] 重连后能收到断线期间的消息，按 seq 升序
- [ ] 收到 `bind_message` 能触发 F07 的上传
- [ ] 心跳失败 3 次判定断线，不无限堆积 goroutine
- [ ] 两条 WS（灵矽 / 我们）同时在线，互不阻塞

## 技术要点

- 两条连接共享一个 `context`，任一致命错误不影响另一条
- `message` 帧解码后投递到播放队列（F09），不要在读循环里做播放
- 重连期间收到的 `bind_message` 直接丢弃（消息已由 TTS 兜底）
