## 背景

同一套 MCP 工具，prompt 写得差就是"听不懂人话"。这部分工作量集中在调优，不在写代码。

## 做什么

- 灵矽控制台：意图识别选**统一意图识别**（Function Call），确认模型支持工具调用
- 编写角色介绍，明确：
  - 什么时候调用 `group.send_voice`（用户要对某个群说一句话）
  - 什么时候反问（群不明、内容为空）
  - 播报要短（≤40 字），不要说"我已经为您将消息发送至……"
- 给每个工具写"何时使用"的描述（可通过设备工具描述 API 覆盖）
- 维护语料集：真实会说的 30 种说法 → 期望的工具与参数
- 用 `linx-emu -say` 批量回归，记录准确率

## 不做什么

- 不改服务端代码（发现问题提给 A）
- 不选音色、不调音量（群消息用原声，TTS 只兜底）

## 验收标准

- [ ] 30 条语料中，工具选择正确率 ≥ 90%，参数抽取正确率 ≥ 85%
- [ ] "给夜班组说一句我快到收费站了" → `group.send_voice{group:"夜班组", text:"我快到收费站了"}`
- [ ] "建个群叫夜班组" → `group.create{name:"夜班组"}`，且播报包含 6 位口令
- [ ] 群名不存在时反问，不杜撰群
- [ ] 单轮回复 TTS 时长 ≤ 8 秒（人工听）

## 技术要点

- 语料要覆盖口语：省略主语、方言词、语序倒装
- 每次改 prompt 记录一版，跑同一套语料，避免"修一个坏两个"
- 识别不准时优先改 prompt，其次考虑改工具描述，最后才改代码
